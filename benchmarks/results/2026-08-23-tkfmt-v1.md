# M1 `tkfmt-1` scalar evaluator baseline — 2026-08-23

This replaces the superseded foobar2000-compatible title-format baseline. The
release build compiled this representative view expression exactly once and
reused the immutable program for every synthetic track:

```text
$if(%artist%,%artist% - ,)%title%$if(%album%, - %album%,)
```

The environment and measurement method match
`2026-08-23-titleformat-foundation.md`: one thread, 256-track pages, warm
in-process synthetic field providers, and a checksum that consumes every
result.

| Tracks | Total | Throughput | 256-track p50 | 256-track p95 | Worst page |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 10,000 | 2.15 ms | 4.65 M/s | 54.67 µs | 59.43 µs | 60.53 µs |
| 100,000 | 22.25 ms | 4.49 M/s | 55.50 µs | 60.14 µs | 245.76 µs |
| 1,000,000 | 222.77 ms | 4.49 M/s | 55.44 µs | 60.38 µs | 353.69 µs |

The expression deliberately exercises two lazy conditionals and repeated field
lookups, so it is more expensive than a plain column. The p95 page time remains
well below the provisional 8 ms visible-page formatting budget. Database fetch,
Qt painting, collation, and cache invalidation are not included and require host
integration measurements in later milestones.

Tree `$each` expansion is separately bounded and tested; this scalar benchmark
does not treat expanded branches as ordinary rows.
