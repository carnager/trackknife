# M0 generated-fixture baseline — 2026-08-23

This is an early engineering baseline, not a product performance claim.

## Environment

- Arch Linux, Linux 7.1.8, x86_64
- AMD Ryzen 7 9700X, 8 cores / 16 threads
- 60 GiB RAM
- GCC 16.2.1, CMake 4.4.2, Ninja 1.13.2
- Qt 6.11.2
- Release preset (`-O3` as selected by CMake/GCC)

## Generated 256-row pages

Command: `./build/release/benchmarks/trackknife_fixture_benchmark`

| Logical tracks | p50 | p95 | Worst |
| ---: | ---: | ---: | ---: |
| 10,000 | 6.30 µs | 8.16 µs | 34.94 µs |
| 100,000 | 6.16 µs | 6.35 µs | 8.16 µs |
| 1,000,000 | 6.74 µs | 7.26 µs | 8.59 µs |

This measures deterministic fixture construction for one 256-row page. It does
not include SQLite, title formatting, Qt queued delivery, painting, scrolling,
artwork, or an actual display server.

## Offscreen launch smoke

`trackknife --smoke-test --rows 1000000` completed in 0.23 seconds using Qt's
offscreen platform. The test verifies construction and event-loop activity, but
is not equivalent to warm launch on a desktop compositor.

## Million-row interaction probe

The release benchmark was run for 240 deterministic samples on the live Wayland
session at 1280 × 800. The model was also receiving explicit background page
refreshes. Measurements include the synchronous Qt operation, queued event
delivery, and repaint requested by the harness. They do not measure physical
display scanout or presentation latency.

| Interaction | Budget | p50 | p95 | Worst |
| --- | ---: | ---: | ---: | ---: |
| Random scroll and repaint | 16.7 ms | 0.24 ms | 9.11 ms | 12.09 ms |
| Selection and repaint | 50 ms | 0.11 ms | 5.26 ms | 9.31 ms |
| Tab switch and repaint | 50 ms | 12.33 ms | 13.24 ms | 16.89 ms |
| Dock move and repaint | 50 ms | 21.95 ms | 36.87 ms | 42.72 ms |
| Saved-layout restore and repaint | 75 ms | 38.03 ms | 65.39 ms | 69.38 ms |
| Background 256-row page load | 50 ms | 3.56 ms | 5.22 ms | 33.55 ms |

The saved-layout budget is 75 ms rather than reusing the 50 ms cached-panel
budget. An initial combined measurement showed that Qt's full `restoreState`
plus repaint took 62.26 ms p95. Separating ordinary dock movement from complete
workspace reconstruction showed dock interaction inside 50 ms, while providing
evidence for a distinct restoration target.

At the end of adversarial random scrolling, the model held exactly its configured
maximum of 48 resident pages. Independent tests assert no more than four page
loads execute concurrently and no more than 16 additional requests wait. Process
RSS grew by 11,788 KiB during the 240-sample run (134,580 to 146,368 KiB); this
includes Qt backing stores and both synthetic track models, not only page data.

An offscreen control run was faster, as expected: scroll 3.01 ms p95, selection
2.14 ms, tabs 4.95 ms, dock movement 14.56 ms, and layout restoration 26.96 ms.

## Evidence intentionally deferred to feature milestones

- accessibility inspection and keyboard navigation at scale;
- measurements with real SQLite rows, compiled title formats, artwork, and audio
  jobs as those implementations replace the synthetic backend;
- actual compositor presentation timing when Trackknife gains a frame-time
  diagnostics hook rather than relying on repaint completion.
